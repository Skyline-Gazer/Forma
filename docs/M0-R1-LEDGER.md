## 1. 缺陷与处置

### 1.1 窗口最小宽度 1845–1941pt（#150）

**现场证据**：1512pt 屏幕上的窗口最小宽度为 1845–1941pt，应用无法在该屏使用。

**根因**：窗口的最小宽度是屏幕上各列最小宽度之和。表格列只声明了 `min` 与
`ideal`，没有上限；未声明上限的列按内容测量，长路径因此变成对窗口宽度的要求。
三个区域的表格都有未声明上限的列（路径列、项目列、候选列）。

**处置**：

- 新增 `FormaCore.Presentation.ShellLayout`：窗口列宽、各表列宽预算与宽度分
  级集中在一处，可被测试读取。
- 新增 `ShellLayoutTests`：逐区域计算最小窗口宽度并锁定在 1280pt 以内；同时
  断言没有无界列、workspace 的两张表纵向堆叠而非相加、宽度分级有序。
- 应用侧所有表格列改为使用该预算（此前未声明宽度的列一并补齐），侧栏、详情
  面板与各区域引导面板的最小宽度同步收紧；归档计划的原因标签由单行改为自适
  应换行网格，不再按标签数量索取宽度。

**结果**：最小窗口宽度 1104pt（映射区域，其余区域更小），低于 1280pt 预算。

**未验证**：真实 macOS 上的窗口尺寸行为（拖拽不改变外框、1200/1280/1512 三档
可用）仍需 Mac 现场复测，见 #153。

### 1.2 陈旧证据被答成“不存在”（#145 / #144）

**现场证据**：修改 PDF 正文并重新扫描后，审核台仍展示旧快照的证据行；引用保存
后被拒绝，表现为 `evidence_not_found`，而不是 `evidence_snapshot_mismatch`。

**根因**：纠正闸门只能看到该来源当前持有的行。旧快照的行仍在库里，闸门却看不
见它，于是把“过期”当成“不存在”；审阅者被告知去找一份从未丢失过的证据。校验
器按证据 id 报告引用类违规，而纠正引擎按字段路径过滤违规，精确原因在这一步
被过滤掉，界面只剩一句泛化的“未生效”。

**处置（Core，#147）**：

- 纠正闸门按 id 在整个注册表中查找被引用的行，因此能区分三种拒绝：注册表从
  未有过该行（`evidence_not_found`）、该行属于别的文件（`evidence_foreign_source`
  ）、该行读不出来（`evidence_unusable`）。
- 引用同时对照两个快照：清单条目绑定的快照与当前清单的快照。文件在清单之后
  改动过时，即使引用的是清单自己的行也判为过期。
- 校验器的引用类违规改为按字段路径报告，纠正被拒时界面拿到的就是精确原因。

**处置（界面，#146）**：

- 新增 `FormaCore.Presentation.EvidenceCurrency`：注册行与当前快照的关系，以及
  界面统一使用的文案。
- 审核台与修订面板在勾选前标出已过期的证据行，并且不再允许勾选；提供「重新
  读取证据」这一可发现的恢复动作，重新读取后清除已失效的旧选择。
- 拒绝代码改由模型以数据形式发布（`lastRefusalCodes`），界面不再从英文提示句
  里反解代码；提示句改为中文，原始代码只保留在「诊断详情」中。
- 失败的修订仍不发布新版本、不清空草稿、不自动进入下一份。

**回归**：`EvidenceCurrencyTests` 覆盖伪造 id、过期行、文件已变更、他文件行、不
可读行，以及“重新读取并重新映射后一次修正成功”的完整链路（Core，#147）。

**未验证**：真实 macOS 上的审核台交互（过期标记、恢复按钮、重新选择后修正成功）
仍需 Mac 现场复测，见 #153。

### 1.3 界面中英混排与 Profile 称呼（#150 / #144）

**现场证据**：侧栏、工具栏与业务提示已是中文，「设置」与「诊断」两个面板仍是
英文句子；Profile 选择器标为“Profile”，占位文案为“未选择 Profile”，而审核台
把同一选择称为“资料库类型”。

**处置**：「设置」「诊断」两个面板的可见文案（分区标题、字段标签、按钮、空状态
与提示句）改为中文，共 145 处；技术标识（Provider、DEVONthink MCP、
initialize/tools/list、UUID、API、CasePack）保持原样。Profile 选择器与占位文案
统一为「资料库类型」。
