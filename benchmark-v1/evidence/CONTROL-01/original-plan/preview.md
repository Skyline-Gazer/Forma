## 保持原位

无。29项均有处置建议；8项因证据不足建议待确认，确认前保持原路径、原名。其余21项建议移动并重命名。项目内重复文件名仅出现在不同角色子目录，不会互相覆盖；公告和授权函等待确认文件名带清单ID避免冲突。执行前如发现目标已存在，应先核对而非覆盖。

## 待确认事项及后果

- 三份授权函需人工确认授权方、被授权人、适用项目、有效期和签章状态。在确认前不归入HC、ED或LG项目，也不能把“授权函”当作真实授权成立的证明。
- 授权函待确认目标名已使用D06/D14/D22区分，避免相互覆盖；确认文号/项目后再统一改为准确名称。
- D26产品介绍只能确认文件名，没有内容证据。D27报价草表不得归属任何单一项目；待确认后可归项目，也可能作为特定产品/供应商资料跨项目引用。D28扫描件无法确认用途或日期。
- D01、D09、D17公告不能由当前本地解析工具可靠读取，均暂列待确认，不依据原目录做项目匹配。此举也避免多个项目中“采购公告.pdf”目标冲突。
- D01/D09/D17公告和D06/D14/D22授权函均用原清单ID作暂定名，避免同名冲突；待人工确认内容后再统一准确命名。其它多项目文档当前唯一；若未来加入同项目的复核稿，应将版本/日期补入文件名，不覆盖现文件。

## 建议业务元数据与 Smart Groups 维度

工具环境未提供本地文件柜/Smart Groups 或文件属性批量编辑能力，因此本节是可实施的元数据建议，不表示已写入文件属性，也不会在工作区制造索引文件。

| 字段 | 示例/用途 |
|---|---|
| 项目编号 | HC26-041；ED26-073；LG25-019；未确认值为空 |
| 项目名称 | 数据中心存储扩容等，使用正文证据 |
| 采购人 | 澄湾市仁泽医院等 |
| 业务角色 | 采购公告、采购技术要求、技术响应、制造商渠道报价、协调记录、最终递交确认、历史模板、授权函、产品介绍、未分类扫描件 |
| 形成方 / 对方 | 采购方、投标主体、制造商或协调方；未写明则未知 |
| 文档状态 | 内部审阅、批准提交、已递交、草表、历史参考、待确认 |
| 版本 | V0.3、V1.0；未标记则留空 |
| 日期属性 | 截止日、文件形成日、递交日分字段；只有截止日可从项目资料读取，不推断形成日 |
| 密级/用途 | 内部成本、内部协调、采购方文件、提交记录等；成本报价应限内部使用 |
| 来源/原路径 | 邮件附件、下载、桌面备份等用于溯源，可只作元数据，不保留为主要目录 |
| 供应商 / 产品 | 启岳科技、矩川科技；未关联报价草表的万兆模块8个 |
| OCR/识别状态 | 可读文本、扫描图像未识别、内容待人工确认 |

推荐 Smart Groups 查询：①按项目编号；②按文档角色；③状态为“待确认”；④“内部成本”报价；⑤状态为“待审阅/批准提交/已递交”；⑥跨项目历史参考；⑦扫描/OCR未识别；⑧按供应商或产品；⑨按截止日期窗口。逻辑集合可同时出现同一文件（例如“HC26-041”“内部成本”），无需重复放置副本。
